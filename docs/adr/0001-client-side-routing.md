# Клиентская маршрутизация через react-router в одном jar

Фронтенд — SPA с несколькими страницами (`/` и `/book`), поэтому маршрутизация на клиенте через `react-router`. Приложение поставляется одним jar Spring Boot, поэтому серверу нужен SPA-fallback: на пути клиентской маршрутизации он отдаёт `index.html`, а дальше маршрутизацию ведёт фронтенд (`SpaFallbackConfig`).

## Considered Options

- Обычная ссылка `<a href="/book">` без роутера и заглушки: проще, но кнопка с главной вела бы на несуществующую страницу.
- SPA-fallback только на перечисленные пути (контроллер с `/book` и `/admin`): точнее, но каждый новый клиентский маршрут требовал бы правки бэкенда. Выбран общий fallback: любой путь не под `/api`, в последнем сегменте которого нет точки.

## Consequences

- В dev-режиме всё работает: Vite сам отдаёт `index.html` на любой путь.
- В собранном jar прямая загрузка или F5 на `/book` и `/admin` возвращают приложение (200).
- Срок SPA-fallback перенесён. Сначала предполагалось добавить его «в тикете страницы записи, пока `/book` — заглушка»; сделан он раньше, до первой настоящей страницы Админки (шаг 0.2 плана раздельной реализации, тикет [«SPA-fallback: прямые переходы на страницы записи и Админки»](https://github.com/SevyConst/ai-for-developers-project-386/issues/24)).
- Неизвестный путь под `/api` и несуществующий файл (например, `/assets/missing.js`) остаются честным 404 от Spring и страницу приложения не получают.
- Неизвестный клиентский путь (например, `/nowhere`) при прямой загрузке получает приложение с HTTP-статусом 200 и клиентской страницей 404 (маршрут `*`): сервер не знает, какие пути есть у фронтенда.
- Страница `/admin` реализована в тикете [«Админка: Типы событий (фронтенд)»](https://github.com/SevyConst/ai-for-developers-project-386/issues/26): кнопка «Админка» на главной и прямая загрузка ведут на неё, а не на клиентскую страницу 404.
