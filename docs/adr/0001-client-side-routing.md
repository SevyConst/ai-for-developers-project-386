# Клиентская маршрутизация через react-router в одном jar

Фронтенд — SPA с несколькими страницами (`/` и `/book`), поэтому маршрутизация на клиенте через `react-router`. Приложение поставляется одним jar Spring Boot, где пока нет SPA-fallback (контроллера, отдающего `index.html` на неизвестные пути).

## Considered Options

- Обычная ссылка `<a href="/book">` без роутера и заглушки: проще, но кнопка с главной вела бы на несуществующую страницу.

## Consequences

- В dev-режиме всё работает: Vite сам отдаёт `index.html` на любой путь.
- В собранном jar переход по кнопке внутри приложения работает, но прямая загрузка или F5 на `/book` вернёт 404.
- SPA-fallback в Spring добавляем в тикете страницы записи, пока `/book` — заглушка. Не «чините» 404 раньше, чем появится реальная страница.
- `/admin` намеренно не реализован: кнопка «Админка» на главной ведёт на него, и внутри приложения показывается клиентская страница 404 (маршрут `*`). Прямая загрузка `/admin` в jar возвращает настоящий 404 от Spring.
