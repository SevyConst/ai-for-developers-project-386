# Контракт в `contract/`: закоммиченный OpenAPI, код потребителей генерируется в сборке

Контракт API пишется на TypeSpec и лежит в `contract/` в корне репозитория, со своими `package.json` и `package-lock.json` и точными версиями `@typespec/*`. Результат — `contract/openapi.yaml` — коммитится и остаётся единственным сгенерированным файлом в git: его меняют только через `.tsp`, генерирует разработчик локально, а свежесть проверяет задача CI `contract` (перегенерация и `git diff --exit-code`). Maven и Docker `tsp` не запускают, а читают готовый файл. Код потребителей (Java-интерфейсы бэкенда, TypeScript-клиент фронтенда) генерируется из `openapi.yaml` в сборке и не коммитится.

## Considered Options

- Контракт внутри `frontend/` (в `frontend/package.json`): одна установка, но зависимости TypeSpec (около 63 МБ) попадают в `npm ci` фронтенда, а контракт «принадлежит» одной из сторон, хотя бэкенд — равноправный потребитель. В `docs/` класть нельзя: `.dockerignore` исключает его из контекста сборки.
- Не коммитить `openapi.yaml`, а генерировать в каждой сборке: `tsp` пришлось бы запускать в Maven раньше `generate-sources` (шаги `frontend-maven-plugin` идут позже, в `generate-resources`), флаги `-Dskip.installnodenpm -Dskip.npm` из `Dockerfile` отключают npm-шаги Maven, а каждая сборка бэкенда тянула бы Node и TypeSpec. Изменения контракта пропали бы из diff в PR.
- Коммитить и код потребителей (в том числе TypeScript-клиент): всё работает сразу после клонирования, но появляется второй сгенерированный артефакт, вторая проверка свежести, шумные diff и исключения в ESLint, Prettier и Checkstyle.

## Consequences

- Забытая перегенерация ловится в CI. Версии TypeSpec закреплены (точные версии и lock-файл): вывод эмиттера между версиями побайтно не гарантирован, и без закрепления проверка свежести падала бы «сама». Обновление TypeSpec — осознанный шаг: поднять версию, перегенерировать, закоммитить `openapi.yaml`.
- `Dockerfile`: в стадиях `frontend-build` и `backend-build` добавляется `COPY contract/openapi.yaml /app/contract/openapi.yaml`. Копируется только файл, чтобы правки `.tsp` и lock-файла не сбрасывали кэш слоёв. Относительный путь `../contract/openapi.yaml` из `backend/` и `frontend/` работает так же, как в репозитории.
- Генерация кода потребителей: бэкенд — в `generate-sources` в `target/`, фронтенд — npm-скриптом перед сборкой в каталог под `.gitignore`. ESLint и Prettier этот каталог игнорируют.
- `contract/openapi.yaml` нельзя править руками: правка пропадёт при следующей генерации.
